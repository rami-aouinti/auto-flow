# Billing Service

Separate financial-document bounded context. Payment owns Stripe and payment state; Billing owns immutable invoices, VAT breakdowns, credit notes and billing queries.

Consumes PaymentCaptured, PaymentRefunded and PaymentPartiallyRefunded from autoflow.payment.events through queue autoflow.billing.payment-events. The Inbox stores a payload fingerprint: exact redeliveries are ignored, while eventId reuse with different contents is rejected. Malformed or unsupported envelopes are published to autoflow.billing.payment-events.dead before the original delivery is acknowledged; transient database failures are requeued. Invoice numbers are tenant/year scoped (AF-YYYY-000001); credit notes use AC-YYYY-000001. Payment creation carries the immutable Customer billing snapshot through Order and Payment. Invoices and credit notes retain issuer/recipient legal snapshots; a captured payment creates an `issued` invoice only when both issuer tax identity/address and recipient billing address are complete. Otherwise it creates a `draft` invoice rather than falsely claiming a legally complete invoice.

API (Keycloak billing:read scope and tenant claim):
- GET /api/v1/billing/invoices
- GET /api/v1/billing/invoices/{id}
- GET /api/v1/billing/invoices/{id}/document — lazily generates and uploads a PDF for a legally complete issued invoice; downloads are proxied from Document Service and SHA-256 verified (drafts return 409)
- GET /api/v1/billing/credit-notes
- GET /api/v1/billing/credit-notes/{id}
- GET /api/v1/billing/summary

BILLING_TAX_RATE_BPS defaults to 1900 (19%). Amounts are treated as VAT-inclusive. This local default is not a multi-country VAT engine. Configure `BILLING_ISSUER_LEGAL_NAME`, `BILLING_ISSUER_TAX_NUMBER` or `BILLING_ISSUER_VAT_ID`, and `BILLING_ISSUER_ADDRESS_JSON` with the actual legal entity details before production. The root `.env.production.example` documents the required legal-entity values; copy it to the ignored `.env.production` and replace every placeholder. Do not issue real invoices until the applicable jurisdiction's tax rules, invoice fields, numbering and retention requirements have been reviewed by a qualified tax/legal professional. Run the live local consumer check with `docker compose --env-file .env.example up -d billing-service billing-payment-event-consumer`, then `docker compose --env-file .env.example exec -T billing-service php bin/smoke-test-payment-events.php`. It verifies captured-payment invoice creation, partial-refund credit notes, exact redelivery idempotency and conflicting-event dead-lettering.

The PDF renderer uses the immutable issuer/recipient snapshot and refuses to render drafts. Document Service owns the canonical invoice PDF bytes, encrypted storage, malware scan, versions and retention; Billing stores only the immutable Document UUID/checksum reference in `billing_document_references`. Invoice document requests require the caller token to include the `autoflow-document` audience and `documents:write` on first generation plus `documents:read` for download. The document owner is the authenticated caller. Run the integration smoke test against a legally complete issued invoice with `DOCUMENT_E2E_TOKEN=... BILLING_E2E_INVOICE_ID=... docker compose exec -T billing-service php bin/smoke-test-document-integration.php`. Jurisdiction-aware tax determination, country-specific statutory invoice fields, archival/retention, accounting exports and legal review remain production requirements; the local 19% rate is not legal/tax advice.
